# 13. Configuration and maintenance

This chapter brings together what PLC-Monitor stores, where it stores it, how to make backups, and what to
review over time. Most settings are made from the app; a few, such as the global history retention, are
changed in `agent.json`.

## 13.1. App files

The app stores its data in the user's configuration folder:

- Linux: `~/.config/PLC-Monitor/`.
- Windows: `%APPDATA%\PLC-Monitor\`.

| File | Content |
|---|---|
| `app.json` | Theme, last connection, and preferences. |
| `agents.json` | Collector profiles, URL, and protected token. |
| `trends.json` | Saved trend views. |
| `panels.json` | Panels and view layout. |

Close the app before copying or restoring these files. If you edit them by hand, make a backup and respect
the JSON format.

On Windows the token is protected with the user's DPAPI. A backup restored under another Windows user will
not be able to decrypt it: enter the token again. On Linux the file has `600` permissions, but the token is
not encrypted with a system key; protect the backup.

## 13.2. Collector files

Default paths:

- Linux: `/opt/plc-monitor/agent/`.
- Windows: `%ProgramFiles%\PLC-Monitor\agent\`.

| File or folder | Content | Included in the backup? |
|---|---|---|
| `plcmon-agent` / `plcmon-agent.exe` | Executable. | Not needed. |
| `agent.json` | Devices, tags, transformations, historian, and OPC UA. | Yes. |
| `agent.key` | Key that decrypts the passwords in `agent.json`. | Yes, it is a secret. |
| `agent.settings.json` | Token, TLS, port, and logging. | Yes, it is a secret. |
| `agent.pfx` | TLS certificate and its key. | Yes, it is a secret. |
| `history/` | SQLite files for history. | Yes. |
| `opcua/` | OPC UA server certificate and accepted clients. | Yes. |
| `logs/` | Logs on Windows; on Linux only if logging to file is enabled. | Optional. |
| `.bundle/` | Internal extraction of the executable on Linux. | No. |

The first four files are secrets or contain secrets. On Linux they must belong to `plcmon` and have mode
`600`; on Windows only the service and administrators should be able to read them.

The Linux service runs with `ProtectSystem=strict`, `ProtectHome=true`, and can only write inside
`/opt/plc-monitor/agent`. If you configure an absolute `historian.path` outside that folder, the historian
will not be able to write. Use a relative path or one inside the collector folder.

## 13.3. agent.json

`agent.json` is the engine configuration. The app maintains it when adding devices, tags, transformations,
and OPC UA settings. Its structure is:

```json
{
  "devices": [],
  "historian": {
    "enabled": true,
    "path": "history",
    "retentionDays": 90,
    "flushIntervalMs": 1000
  },
  "transforms": [],
  "opcUa": {
    "enabled": false,
    "port": 4840,
    "allowWrites": false,
    "users": []
  }
}
```

The names the app writes are camelCase. The file accepts comments and trailing commas.

### Historian

- `enabled`: enables or disables recording. If it is disabled, tags keep their configuration but nothing is
  stored.
- `path`: folder for the files, relative to the collector folder unless absolute.
- `retentionDays`: number of days samples are kept. `0` means no limit.
- `flushIntervalMs`: how often accumulated samples are flushed. A low value protects better against an
  interruption, but writes more to disk.

Retention is applied every 6 hours and deletes whole months or, in the boundary month, samples older than
the limit. Deleting samples from the app does not necessarily reduce the size of the SQLite file: SQLite
reuses the free space. To recover disk space, export what you need and delete old monthly files with the
service stopped.

### Editing by hand

Do it with the collector stopped or restart it right afterward. If the app saves a change while you have the
file open, it may overwrite your edit. Before editing:

```bash
sudo systemctl stop plcmon-agent
sudo cp -p /opt/plc-monitor/agent/agent.json /opt/plc-monitor/agent/agent.json.bak
```

On Windows, stop and copy with PowerShell as administrator:

```powershell
Stop-Service PLCMonitorAgent
Copy-Item "$env:ProgramFiles\PLC-Monitor\agent\agent.json" "$env:ProgramFiles\PLC-Monitor\agent\agent.json.bak"
```

Then validate the JSON, start the service, and check that it appears in the app. If the collector does not
start, restore the backup.

Do not edit `agent.key` or change encrypted passwords by hand. If you need to change a password, do it from
the app.

## 13.4. agent.settings.json

This file is generated by the installer and contains:

- the SHA-256 hash of the full token and, if requested, of the read-only token;
- the HTTPS URL and port;
- the path and password of `agent.pfx`;
- optionally, logging settings.

Example with hidden values:

```json
{
  "Agent": {
    "Security": {
      "TokenSha256": "…",
      "ReadOnlyTokenSha256": "…"
    }
  },
  "Kestrel": {
    "Endpoints": {
      "Grpc": {
        "Url": "https://0.0.0.0:5311",
        "Certificate": {
          "Path": "agent.pfx",
          "Password": "…"
        }
      }
    }
  }
}
```

Do not edit it to “put the token in plaintext”: only the hash goes here. To change the token, port, or
certificate, use **Renovar credenciales** (Renew credentials) or reinstall from the app. Those operations
rewrite the file; any manual changes you have made to it are lost.

You can override settings with environment variables with the `PLCMON_` prefix and a double underscore, for
example `PLCMON_Logging__LogLevel__Default=Debug`. In systemd, add them with a `drop-in`; do not put them in
`ExecStart` if they contain secrets.

## 13.5. Backups

### What to copy

Always copy:

1. `agent.json`;
2. `agent.key`;
3. `agent.settings.json`;
4. `agent.pfx`;
5. `history/`;
6. `opcua/`.

And, if you want to preserve the app configuration, `app.json`, `agents.json`, `trends.json`, and
`panels.json`.

**Important**: `Conservar agent.json al desinstalar` saves only `agent.json` and `agent.key`. It does not
save history, the certificate, or the OPC UA clients. If you want to preserve them, make a full backup
first.

### How to back up the collector

So that SQLite and the historian are consistent, stop the service before copying.

Linux:

```bash
sudo systemctl stop plcmon-agent
sudo tar -C /opt/plc-monitor --exclude=agent/.bundle \
  -czf /var/backups/plcmon-agent-$(date +%F).tar.gz agent
sudo chmod 600 /var/backups/plcmon-agent-$(date +%F).tar.gz
sudo systemctl start plcmon-agent
```

Windows, in PowerShell as administrator:

```powershell
Stop-Service PLCMonitorAgent
Compress-Archive "$env:ProgramFiles\PLC-Monitor\agent" "D:\backups\plcmon-agent.zip" -Force
Start-Service PLCMonitorAgent
```

Check that the backup contains `agent.json`, `agent.key`, `agent.settings.json`, `agent.pfx`, and the
`history/` folder. If the collector was running, there may be `-wal` and `-shm` files: include them; they are
part of the database.

### Restore

1. Stop the service.
2. Save the current folder just in case.
3. Restore the contents.
4. Adjust owner and permissions.
5. Start and check devices, history, and OPC UA.

Linux:

```bash
sudo systemctl stop plcmon-agent
sudo mv /opt/plc-monitor/agent /opt/plc-monitor/agent.antes
sudo tar -C /opt/plc-monitor -xzf /var/backups/plcmon-agent-2026-10-23.tar.gz
sudo chown -R plcmon:plcmon /opt/plc-monitor/agent
sudo chmod 600 /opt/plc-monitor/agent/agent.json /opt/plc-monitor/agent/agent.key \
  /opt/plc-monitor/agent/agent.settings.json /opt/plc-monitor/agent/agent.pfx
sudo systemctl start plcmon-agent
```

Windows: restore the folder with the service stopped and reapply the restricted ACLs to
`agent.settings.json` and `agent.pfx`.

The backup contains secrets. Store it encrypted, with limited access, and outside the collector computer. Do
not upload it to a repository or public storage.

### App backup

Close the app and copy the entire folder. To restore on another computer:

- Linux: copy the files and preserve `600` permissions on `agents.json`.
- Windows: the token may not decrypt under another user. Enter it again in the profile.

## 13.6. Updates

**Instalar / actualizar** (Install / update) on the **Colectores** tab (Collectors) replaces the executable and
preserves, by default:

- `agent.json` and `agent.key`;
- `agent.settings.json` and `agent.pfx`, if you do not check **Regenerar token y certificado** (Regenerate
  token and certificate);
- `history/` and `opcua/`; on Windows also `logs/`.

During the update the service stops and starts again. On Windows, if an antivirus or the indexer blocks the
executable, the installer retries and, if it cannot, starts the previous version again. In that case, check
the antivirus and try again.

Before updating:

1. Make a full backup.
2. Read the release notes.
3. Check that you have physical or remote access to the computer.
4. Avoid doing it at a critical production moment.

If you check **Regenerar token y certificado**, the previous token stops working and the app updates the
profile. Any script or client that used the previous token will fail. Update it.

After updating:

- check that the collector is **Conectado** (Connected);
- check that the devices are **Conectados** (Connected);
- open history and a trend;
- if you use OPC UA, check that the server is active and that clients connect;
- review the log in case there are new notices.

Do not copy an executable by hand over the running service. Use the app or stop the service first.

## 13.7. Logs

### Linux

```bash
sudo journalctl -u plcmon-agent -n 200 --no-pager
sudo journalctl -u plcmon-agent -f
```

The log includes startup, the loaded configuration, connection errors, and the audit. journald applies its
own rotation.

To also save to a file, add a `drop-in` to the service:

```bash
sudo systemctl edit plcmon-agent
```

```ini
[Service]
Environment=PLCMON_Logging__File__Path=/opt/plc-monitor/agent/logs
Environment=PLCMON_Logging__File__RetentionDays=30
```

Then:

```bash
sudo systemctl daemon-reload
sudo systemctl restart plcmon-agent
```

The files are named `plcmon-agent-YYYYMMDD.log`.

### Windows

The collector writes to `%ProgramFiles%\PLC-Monitor\agent\logs\`, one file per day, with a default retention of
7 days. Event Viewer receives only notices and errors. The app can show the last lines with **Ver log**
(View log).

### What to check

- connection errors to the PLC and retries;
- passwords that cannot be decrypted;
- write errors;
- configuration changes;
- OPC UA certificate acceptance;
- lack of space or SQLite errors.

## 13.8. Periodic maintenance

### Every day

- Check that the collector and devices are connected.
- Check whether there are tags in **Bad** or devices in **En fallo** (Failed).
- Make sure recent history has data.

### Every week

- Review the log for repeated errors.
- Check free space and the size of `history/`.
- Check that trends and panels still show what is expected.
- If you use OPC UA, check that there are no unreviewed rejected clients.

### Every month

- Make a full backup and verify that it can be restored.
- Review history retention and the space it occupies.
- Review OPC UA users and certificates; remove those that are no longer used.
- Check for available updates.
- Check that the collector and PLC clocks are synchronized.

### Every year or when something changes

- Renew tokens and certificates if there have been personnel or network changes.
- Review the list of people with access to the computer and to backups.
- Review the TLS certificate; the one generated by the installer lasts 10 years, but a host migration or a
  name change requires renewing it.
- Review the incident response procedure.

## 13.9. Moving the collector to another computer

1. Stop the old collector and make a full backup.
2. Install the collector on the new computer from the app. New token and certificate are generated.
3. Stop the new service.
4. Copy `agent.json`, `agent.key`, and `history/`. Adjust owner and permissions.
5. Start the service.
6. Update the app profile with the new URL and token.
7. If you use OPC UA, accept the client certificates again or copy `opcua/` only if the host name and
   certificate are still valid.

Do not copy `agent.settings.json` from the old computer unless you want to keep the same token and
certificate. If the host name changes, the certificate may not validate.

## 13.10. Uninstall

From **Colectores** (Collectors), **Desinstalar** (Uninstall) stops the service, removes the firewall rules, and
deletes the collector folder.

If you check **Conservar agent.json al desinstalar** (Keep agent.json on uninstall), copies of `agent.json`
and `agent.key` are saved in:

- Linux: `/opt/plc-monitor/agent.json.backup` and `/opt/plc-monitor/agent.key.backup`.
- Windows: `%ProgramData%\PLC-Monitor-agent.json.backup` and
  `%ProgramData%\PLC-Monitor-agent.key.backup`.

Everything else is deleted: history, certificate, token, and OPC UA clients. Make a full backup first if
you need any of that.
